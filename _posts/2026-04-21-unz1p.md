## **Recognition Pattern**
- SMTP + TCP in a pcap → an email exchange, so export via File → Export Objects → IMF
- An email with a Base64 attachment → decode it to recover the file
- The archive wanted a password → look elsewhere in the traffic, especially SMTP AUTH which is Base64 in plaintext
- "Use the usual mailbox password" → credential reuse, the zip password is the same as the email login sitting in the traffic

## **Approach and Methodology**
### **Initial Analysis**
I opened the file in Wireshark and realized it's a mail scenario (SMTP + TCP). The mail contains an archive, and I believed the flag was inside a file within that archive.

I took the Base64 attachment and, in CyberChef, translated it from Base64 to hex:  

![CyberChef converting the Base64 attachment to hex](Unz1p_1.png)

I saved the hex in a `.txt` file and converted it to an archive with:
```bash
xxd -p -r hex > hex.zip
```
This was successful (checked with `file hex.zip`). The next part was tricky: trying to unzip with `7z x hex.zip` hit a password requirement. So I went back to Wireshark to look for a login, and found it in plaintext (Base64). I decoded it to plaintext.  

![SMTP AUTH credentials found in the pcap, Base64-decoded](Unz1p_2.png)

There was a small trick — the value stored in the packet was username and password together, but once I typed in the password, the archive unzipped.  

## **Solution and Flag Retrieval**
*Final Exploit / Command Used:* opened the extracted file (unzipped with the SMTP AUTH password recovered from the pcap).  

## **Lessons Learned**
- SMTP AUTH sends credentials as Base64, not encrypted — filtering `smtp` and decoding the `AUTH` Base64 gave me the username and password.
- "Use the usual password" was the credential-reuse tell — the same email login opened the zip, so I never needed to brute-force it.
- Wireshark's IMF export pulled the whole email including the attachment in one go, faster than following the TCP stream by hand.
- The attachment recovery was: grab the Base64 block between the MIME boundaries → decode to hex → `xxd -p -r hex > hex.zip` to rebuild the archive.
- Small trick that tripped me up: the AUTH packet held the username and password together, so I had to pull just the password out before it unzipped.
