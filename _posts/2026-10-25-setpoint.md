## **Challenge Information**
**Title:**  Setpoint  
**Category**:  networking (listed as Forensics at RSTCON)  
**Platform:**  RSTCON  
**Difficulty:**  easy  
**Tags:**  pcap, wireshark, Modbus, Modbus-TCP, ICS, write-multiple-registers  
**Date solved:**  25/10/2026 (DD/MM/YYYY)  
**Challenge Description**:  After a maintenance window, a tank controller's alarm config block was rewritten in a single burst. Recover what was pushed into the config registers from the capture.  
**Files provided**:  setpoint.pcap  

## **Environment and Tools** 
**Operating System**:  Kali Linux (Parallels)  
**Tools/ Software**:  wireshark  
**Programming Languages (if any)**:  bash  

## **Recognition Pattern**
- A pcap with a lot of Modbus/TCP traffic => look at what was written to the registers
- The description says the config block was rewritten "in a single burst" => multiple registers written at once (function code 16 = Write Multiple Registers)

## **Approach and Methodology**
Since a .pcap was provided, i opened it in wireshark. Similar to the other challenge ([Coil Toss]({{ '/posts/coil-toss/' | relative_url }})) it had a lot of Modbus/TCP packets, so i filtered to queries only.

> Note: When filtering modbus, you should try : modbus.func_code ==5/6 for writing a single coil/register and modbus.func_code ==15/16 for multiple coils/registers written 

```bash
modbus.func_code ==16
```

There were only two packets, and one contained the middle part of the flag.

## **Solution and Flag Retrieval**
Final Exploit / Command Used:  modbus.func_code ==16  
![Wireshark showing the Write Multiple Registers packet](Setpoint_1.png)

## **Lessons Learned**
- filters help a lot when in wireshark
- When filtering modbus, you should try : modbus.func_code ==5/6 for writing a single coil/register and modbus.func_code ==15/16 for multiple coils/registers written
