**Challenge Description**:  Our field agents intercepted an encrypted message along with the target's RSA public key. Intelligence suggests the key might have its factors leaked. Can you find the factors and decrypt the message?  
**Files provided**:  a text file with the intercepted transmission (public key + ciphertext + analyst notes):  

```
============================================================
INTERCEPTED TRANSMISSION - TOP SECRET
============================================================
Our field agents intercepted an encrypted message from a
target's server. We managed to extract the public key and
the ciphertext. Your mission: break the encryption and
recover the plaintext message.

------------------------- PUBLIC KEY & CIPHERTEXT -------------------------
n = 474284397516047136454946754595585692350335633429396906883713885649480938275214189
e = 65537
c = 385858087101390690069739265636001616416238972658836435480350105437615268070727705

------------------------- ANALYST NOTES -------------------------
RSA security depends on the difficulty of factoring the modulus 'n' into its two
prime factors 'p' and 'q'. If you can find p and q, you can compute:
    phi(n) = (p - 1) * (q - 1)
    d = e^(-1) mod phi(n)   (modular inverse)
    m = c^d mod n           (plaintext as integer)
Then convert 'm' from an integer back to bytes to read the message.
Good luck, agent.
============================================================
```

## **Approach and Methodology**
### **Initial Analysis**
When I first opened the file I was confused and couldn't understand what I was supposed to do, so I went back and re-read the challenge description and looked through the resources attached to the assignment on Classroom. I found a Wikipedia page on the RSA cryptosystem. After reading it I understood I first had to find the two prime numbers whose product is `n`, then do some math using the formulas provided in the file.  

### **Steps Taken**
Another resource attached to the assignment was factordb.com, a site where I entered `n` (the number that's supposed to be the product of two primes).  

![factordb showing the factorization of n](RSA_Leak_1.png)

The prime numbers are:
```
p = 21778071482940061661655974875633165533211
q = 21778071482940061661655974875633166533399
```

Next I wrote a short Python script to do the remaining steps described in the file. I could probably have done all the math by hand, but the script was faster and easier. I plugged in the given variables plus the two primes, calculated `phi(n)`, `d`, and decrypted `m`. Finally, to get a readable message, I converted the integer back into bytes.  

```python
n = 474284397516047136454946754595585692350335633429396906883713885649480938275214189
e = 65537
c = 385858087101390690069739265636001616416238972658836435480350105437615268070727705
p = 21778071482940061661655974875633165533211
q = 21778071482940061661655974875633166533399

if __name__ == "__main__":
    phi = (p - 1) * (q - 1)
    d = pow(e, -1, phi)
    m = pow(c, d, n)
    print(m.to_bytes((m.bit_length() + 7) // 8, 'big').decode())
```

Another version of the solution:  

```python
#!/usr/bin/python
from Crypto.Util.number import inverse, long_to_bytes

n = 474284397516047136454946754595585692350335633429396906883713885649480938275214189
e = 65537
c = 385858087101390690069739265636001616416238972658836435480350105437615268070727705

# used factordb to get the prime numbers
p=21778071482940061661655974875633165533211
q=21778071482940061661655974875633166533399

phi=(p-1)*(q-1)
d=inverse(e,phi)
m=pow(c, d, n)

print(long_to_bytes(m))
```

## **Lessons Learned**
- First real takeaway: when a challenge hints the factors are "leaked" or "weak", paste `n` into factordb before anything else. It had the factorization sitting right there.
- Once you've got `p` and `q`, decryption is just the formula from the notes: `phi = (p-1)(q-1)`, `d = e⁻¹ mod phi`, `m = c^d mod n`. I let a short Python script do it, but I could have done the math by hand.
- The step I nearly forgot was the last one — the result comes out as an integer, so you have to convert `m` back to bytes to actually read the message.
