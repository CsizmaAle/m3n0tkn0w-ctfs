## **Recognition Pattern**
- The URL loaded a file by name (`?name=charlie.txt`) — a parameter reading a file straight off disk is my LFI tell
- The hint literally handed me the filename (`flag.txt`), so the move was to feed that into the same parameter
- `flag.txt` on its own didn't load, so I tried a leading `/` and `../` to point somewhere other than the dogs directory

## **Approach and Methodology**
### **Initial Analysis**
I opened the web page and looked at all the dog profiles, thinking I’d have to do some sort of injection or tamper with the URL.  

### **Steps Taken**
I opened the webpage and clicked into one of the dog profiles. The URL revealed the vulnerability immediately:  

```
http://194.102.62.166:30650/dog?name=charlie.txt
```

The `name` parameter was loading a file by name — classic LFI candidate. Since the hint mentioned `flag.txt`, I tried substituting it directly:  

```
http://194.102.62.166:30650/dog?name=flag.txt
```

This returned an error, meaning `flag.txt` wasn't in the same directory as the dog files. I tried absolute path from root:  

```
http://194.102.62.166:30650/dog?name=/flag.txt
```

That returned the flag. The leading `/` made the server look at the filesystem root instead of the dogs directory.  

### **Alternative Approaches (if applicable)**
Directory traversal (`../flag.txt`, `../../flag.txt`) would also have worked if the flag was outside the web root.   

## **Solution and Flag Retrieval**
*Final Exploit / Command Used:* changed the name of the dog in the url for the flag file:
```
http://194.102.62.166:30650/dog?name=/flag.txt
```


## **Lessons Learned**
- Main takeaway: a URL that loads files by name (`?name=something.txt`) is the LFI signal — I just swap in the file I actually want.
- `flag.txt` alone failed because it looked in the dogs folder; the leading `/` in `/flag.txt` made it read from the filesystem root instead. That one slash was the whole difference between a relative and an absolute path.
- If the flag had been outside the web root, `../flag.txt` (going up directories) would've been the next thing I tried.
