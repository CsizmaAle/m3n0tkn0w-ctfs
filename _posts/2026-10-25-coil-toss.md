## **Recognition Pattern**
- A pcap with HMI / PLC traffic => an industrial protocol, here Modbus/TCP
- The description says something was "written" to a register => filter for the write requests (function code 6 = Write Single Register)
- The written values are all between 48 and 119 => ASCII characters

## **Approach and Methodology**
Since the file provided was a pcap, I decided to open it in wireshark. The packets captured were all TCP packets. 

I tried to go manually through them, but nothing popped up. So i looked more closely at the challenge description. The register was poked, and something was written, and since the communication used Modbus/TCP i can use the following filter: modbus.func_code == 6

Now, the next step was a nice tricky one. Inside the packets, in the Modbus>Register, there were some numbers that looked interesting. Some values written. I had to copy them and since the numbers were from 48-119 they might be ASCII values.

So i wrote a python script to decode the message.
```python3
#!/usr/bin/env python3

list=[102, 99, 48, 54, 95, 119, 114, 105, 116, 101, 115, 95, 100, 111, 110, 116, 95, 108, 105, 101 ]
text=""

for i in list:
	text+=chr(i)

print(text)
```

To run the script i had to also change the permissions: chmod +x ./solver.py

## **Solution and Flag Retrieval**
Final Exploit / Command Used:  I ran the script and put the flag back together.  
rstcon{ + output of solver + }

## **Lessons Learned**
- Modbus can hide values transmitted one by one and it would not be immediately visible (you have to look for it)
