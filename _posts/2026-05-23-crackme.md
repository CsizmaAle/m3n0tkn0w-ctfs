**Challenge Description**:  A small native program asks you for the flag and tells you whether you got it right. It never prints the flag itself — it only checks. Open it up, figure out what it does to your input and work backwards using a reverse engineering framework such as IDA, Ghidra, Binary Ninja, Iaito or others. You get one file. There are five reversible steps between your input and the comparison the program makes. Undo them and you have the flag.

## **Recognition Pattern**
- "Asks for the flag and tells you if you're right" → a classic crackme, so I reverse the check to pull the flag back out
- "Five reversible steps" → each transform undoes in reverse order, so I work backwards from the compared bytes
- A `memcmp` against a hardcoded `target` → find those target bytes in the binary and undo every transform applied to my input
- `strings` showing "Correct!" / "Nope." confirmed it's just a checker, no network needed for the logic
- The length check (`lungime_input == 0x1f` = 31) told me the exact flag length, handy for sanity-checking the result

`main` has all five steps that need to be reversed to solve the CTF:
1. copy: move the input to the front of the buffer
2. reverse the string
3. XOR with `0x42`
4. add the byte index to each byte
5. nibble swap

All that's left is to find `target` in Ghidra and reverse the steps on it to get the flag. I found `target` in Ghidra and wrote the script. The target contains the `0x53` byte as well, even though it's moved to the next thing:

## **Solution and Flag Retrieval**
*Final Exploit / Command Used:* `python3 solve.py` on the target bytes read out of Ghidra.

```python
target = [
    0xf3, 0x72, 0x37, 0x43, 0x43, 0x67, 0xa3, 0x87, 0x83, 0x62,
    0xb7, 0xa3, 0x53, 0xe2, 0x48, 0xf3, 0x13, 0xe2, 0x38, 0x14,
    0x64, 0x44, 0x98, 0x84, 0x15, 0xa2, 0xb1, 0x62, 0x23, 0x13,
    0x53,
]

def nibble_swap(b):
    return ((b >> 4) | (b << 4)) & 0xff

a = []
for i in range(31):
    c = nibble_swap(target[i])   # undo step 5 (nibble swap)
    b = (c - i) & 0xff           # undo step 4 (add index)
    a.append(b ^ 0x42)           # undo step 3 (XOR 0x42)

flag = bytes(a[::-1])            # undo step 2 (reverse)
print(flag.decode())
```

## **Lessons Learned**
- The crackme pattern: input → transforms → compare against a target. To solve I find the target and undo each transform in reverse order — the last operation applied is the first one undone.
- The five steps and how I reversed them: nibble swap undoes with the same nibble swap, `+i` undoes with `-i`, XOR `0x42` undoes with XOR `0x42`, and reversing the string undoes by reversing again (`[::-1]`). The initial copy into the buffer had nothing to undo.
- Nibble swap and XOR are both their own inverse — spotting the self-reversing steps saved me effort.
- Doing byte math in Python I had to mask with `& 0xff` to stay in 0–255; `(c - i) & 0xff` handles the underflow correctly.
- Finding `target` in Ghidra was just following the variable referenced in `memcmp` to its address in the data section — those raw bytes are the starting point for reversal.
- `strings` was a good first move but never solves a crackme on its own — it confirmed the binary is a flag checker, but I needed Ghidra's decompilation (close enough to C to read directly) to actually see the transforms.
