## **Recognition Pattern**
- "Recover the hidden archive" → a file was transferred through the traffic and I need to reconstruct it
- DNS TXT records carrying hex with sequence numbers → ordered file exfiltration over DNS, so reassemble in order
- Hex starting with `1f8b08` → GZIP signature, so decompress once it's rebuilt
- A "cache sync" with invalid messages followed by hex → disguised data transfer, not real DNS cache operations
- Same idea as Hidd3n but a whole file instead of a bit of text

## **Approach and Methodology**
### **Initial Analysis**
Ran `binwalk` and `cat` to check for hidden messages, then opened the file in Wireshark. I knew I'd use Wireshark since it was a networking CTF and the file was a `.pcap`.  

### **Steps Taken**
Opened the file in Wireshark (`wireshark challenge.pcap`). There isn't a lot of traffic, so I went through it manually and found the context: an exchange of messages. The first few were normal, then there was a cache sync with an invalid message followed by hex code.  

To make retrieving the hex easier, I filtered the packets to `dns.response_to` (standard query responses). Then I copied the TXT value (Domain Name System (response) → Answers) from all 8 responses:

```
002:45d57fc703e3b98fb3d94fa5892548a968cff6d1
005:6fe05d2fb1ce33c4bf58d76ea0303e0185b5cc6a
003:bac3e9681bbb309072410142e5610ea3f2edde5d
004:2fed9690bdace20962a5c43e06f4b924f081622e
006:d6982b89e9facec4bce0c48dc9b0baa4d6048d91
000:1f8b08000000000002ff2d8cbb0ec2300c457f25
001:cadc480831b13231b740b7284adc266a7190ed42
007:0c68c605bfe565f71fe063f253aa000000
```

Afterwards I ordered them and removed the `00nr:` prefixes to get the hex of a file:

```
1f8b08000000000002ff2d8cbb0ec2300c457f25
cadc480831b13231b740b7284adc266a7190ed42
45d57fc703e3b98fb3d94fa5892548a968cff6d1
bac3e9681bbb309072410142e5610ea3f2edde5d
2fed9690bdace20962a5c43e06f4b924f081622e
6fe05d2fb1ce33c4bf58d76ea0303e0185b5cc6a
d6982b89e9facec4bce0c48dc9b0baa4d6048d91
0c68c605bfe565f71fe063f253aa000000
```

A quick search on the header showed it was a GZIP-compressed file. So I had to convert the hex to an archive.  

I saved the hex in a separate `hex.txt` and opened the terminal. I was stuck, so I asked Claude.ai for help and it recommended `xxd -r -p`.  

I ran `xxd -r -p hex.txt > archive.gz`, got the archive, and unarchived the file inside.  

## **Solution and Flag Retrieval**
*Final Exploit / Command Used:*
```
xxd -r -p hex.txt > archive.gz
```
Inside the archive was a single file that contained the flag I was looking for.  

## **Lessons Learned**
- Recognizing the magic bytes from hex paid off — `1f8b` at the start told me it was GZIP before I'd even rebuilt the file.
- `xxd -r -p hex.txt > archive.gz` is what turned the raw hex text back into the binary file (`-r` for reverse, `-p` for plain hex). I was stuck on this step until Claude pointed me at it.
- The TXT records came out of order (002, 005, 003, 004...), so I had to reorder by sequence number and strip the `00nr:` prefixes before concatenating — assembling as-is would've given a corrupted archive.
