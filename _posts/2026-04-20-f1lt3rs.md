## **Recognition Pattern**
- A `.pcap` provided → open it in Wireshark, it's a traffic capture
- "Search for the flag" with no other hints → the flag's probably plaintext somewhere in the packet data, so I string-search
- Before anything complex, search for the known flag prefix (`UVTICS{`) in the packet bytes
- Checking the file with `binwalk`/`file` first is a good instinct, just to be sure it isn't hiding something else

## **Approach and Methodology**
### **Initial Analysis**
First I checked the file with `binwalk` to make sure it's just a `.pcap` with nothing hidden, then opened it in Wireshark to search for the flag.  

### **Steps Taken**
Opened the file in Wireshark (`wireshark challenge.pcap` in the terminal), then `Ctrl+F`. In the search bar, set it to **Packet bytes** and **String**.  

### **Alternative Approaches (if applicable)**
Manually go through each row in Wireshark and search for the flag, but that might take a while with a lot of traffic. Another way could be `grep` — the file is binary, but if converted to text this might work.  

## **Solution and Flag Retrieval**
*Final Exploit / Command Used:* entered the `UVT` string in the filter bar and got the flag.  

![Wireshark packet-bytes string search finding the flag](F1lt3rs_1.png)

## **Lessons Learned**
- First move on any pcap: `Ctrl+F` → set the filter to "Packet bytes" + "String" → search the flag prefix. It took seconds and solved this one outright.
- The search mode matters — "Display filter" searches headers/metadata, "Packet bytes" searches the raw data inside packets. For flag hunting I want Packet bytes.
- `strings challenge.pcap | grep -i UVTICS` from the terminal would've worked too and is even faster — `strings` handles the binary file fine, no conversion needed.
