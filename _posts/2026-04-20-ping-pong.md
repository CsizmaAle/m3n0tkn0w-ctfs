## **Recognition Pattern**
- "Ping-pong" / "Focus on the unseen" → ICMP traffic, data hidden in ping packets where you wouldn't normally look
- Ping packets with unusually large data fields → data smuggled in the ICMP data field of the requests/replies

- Normal-looking ping traffic but odd packet sizes → inspect the ICMP data field, not just the headers

## **Approach and Methodology**
### **Initial Analysis**
Ran `binwalk` and `cat` to check for hidden messages, then opened the file in Wireshark. I knew I'd use Wireshark since it was a networking CTF and the file was a `.pcap`.

## **Solution and Flag Retrieval**
*Final Exploit / Command Used:* copied the hex from each sequence (in order), pasted it into CyberChef's "From Hex", and got the flag.  

## **Lessons Learned**
- The ICMP data field is normally just padding — here it was swapped out for actual data, a covert channel firewalls rarely inspect.
- In Wireshark, filtering `icmp` and expanding "Internet Control Message Protocol" → "Data" showed the raw payload in each packet.
- The data was split across packets with sequence numbers, so I reassembled it in order before decoding.
- The workflow was two hex passes: hex→ASCII first revealed `seq=XX;hex=YYYY`, then I concatenated the `YYYY` values in order and did hex→ASCII again for the flag. CyberChef chained both.
- Same idea as the DNS exfiltration in Hidd3n, just a different protocol — abuse a field nobody watches to smuggle data out.
